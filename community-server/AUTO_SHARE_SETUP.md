# v0.7.5 自動送信の導入

APKの更新に加え、Cloudflare側もこの変更を一度反映してください。
この環境にはCloudflareアカウントの認証情報がないため、本番への反映は未実施です。

## 既存サーバーを更新する

1. `KaimonoScan-v0.7.5-server-update.zip` を、以前にデプロイした既存の `community-server` フォルダー内へ展開して上書きします。`src` と `migrations` が既存の同名フォルダーに重なる位置です。この差分ZIPには `wrangler.jsonc`・秘密情報・投稿用キーを含みません。
2. `RUN_SERVER_UPDATE.cmd` をダブルクリック。DB移行の確認は内容を確認して `y`。既存のD1へ新しいテーブルを追加してからWorkerを更新します。既存の価格・招待キーは残ります。
3. `/health` に `"auto_bindings": true` が出れば反映済みです。APKを上書き更新し、商品を登録してください。更新前のサーバーへ送れなかった分は、アプリの再起動か設定の「自動送信の未送信データ」から再送できます。

コマンドで実行する場合（既存 `community-server` 内）：

```powershell
npx.cmd wrangler d1 migrations apply kaimono-community --remote
npx.cmd wrangler deploy
```

全文ソースZIPから作業する場合は、既存の実際の `database_id` が入った `wrangler.jsonc` を必ず引き継いでください。差分ZIPなら設定ファイルを上書きしません。DB名を独自に変更していた場合は、上記のDB名をその名前に読み替えます。

## 送られるデータ

商品追加・修正で確定したJAN、商品名、1個分の税込価格、登録日、手入力/セブン掲載の区分、セブンの場合は公式商品URL。セブンは初回ひも付け、再取得・24時間以内のキャッシュ利用時に送信し、更新失敗の古い保存値は送信しません。数量を増やすだけ、共有DBからの再取得、既存の手入力保存値の読込では再投稿しません。数量・残高・カメラ画像・位置情報・Yahoo! ID・キーは送信しません。

自動送信は初期ON。アプリの設定でOFFにできます。未送信は端末に保存（最大100件）、同じ登録内容を1日内で繰り返し送らず、通信失敗時も同じ投稿IDを使います。アプリ起動中は約1分後に再試行、起動時・再送ボタンでも試行します。アプリを閉じた間のバックグラウンド送信はありません。送信先を変更した場合、旧接続先向けの未送信を新接続先へ転送しません。

## 管理・公開

自動収集は `auto_bindings` の審査待ちに保存。店頭確認済みの `price_reports` とは分けます。アプリへのキー入力は不要ですが、公開の承認・却下には既存の管理用キーが必要です。

```powershell
py -3 admin.py bindings
py -3 admin.py approve-binding "表示されたID"
py -3 admin.py reject-binding "表示されたID"
```

既存の `COMMUNITY_API_URL` と `COMMUNITY_ADMIN_TOKEN` を使います。承認後に別端末のバーコード検索にも表示されます。手入力は「店舗未確認」、セブンは「掲載価格の共有値」と表示し、店頭価格と混同しません。

匿名受付は日ごとのIP由来ハッシュで通常50件/日（`AUTO_DAILY_LIMIT`、最大100）、全体5000件/24時間まで。IP原文はDBへ保存せず、ハッシュは公開レスポンスへ含めません。上限は単一SQLで判定し、受付済みIDの再送は上限到達後も同じ受付結果を返します。自動投稿の内容自体は管理者確認が必要です。
